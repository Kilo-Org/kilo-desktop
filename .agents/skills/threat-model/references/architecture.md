# Architecture Map — Trust Boundaries → Files → Candidate Threats

`template-questions.md` says *what to answer*; this file says *where to look*;
`docs/security/threat-model.md` records *the verdicts*. Threats in the Candidate
threats column are hypotheses to verify, not findings.

Two rules:

1. **Seed, not exhaustive** — also look for threats NOT listed here when reading
   code. The map accelerates; it must not blinker.
2. **Maintenance trigger** — a PR that adds a trust boundary (new plugin sidecar,
   network listener, credential store, file IPC) must add a row. This file absorbs
   architecture drift so `SKILL.md` and `template-questions.md` stay stable.

Note: features migrate `apps/ → plugins/ → external repo` (see `CONTEXT.md`), so
boundary files WILL move — Phase 0 in `SKILL.md` exists to catch that.
