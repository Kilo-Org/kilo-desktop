# Workbooks

A workbook is where the information from chats about one piece of work is kept, by the user and by several agents, so that work outlives any one chat or session. Workbooks are created from **workbook templates**. Design and decisions live in the workbooks themselves (see "Workbooks (Spike)" and "Workbooks: first cut" in Pages).

The pre-rolled templates (Coding; Blank) live in `plugins/workbooks/templates/` and ship as built-ins through kilo.workbooks' own `kilo.workbooks/template` extension point; other plugins contribute templates the same way. A contribution's `read()` returns the template with its content resolved (`WorkbookTemplate` in kilo.workbooks' contracts); invalid templates are skipped and reported in `kilo.workbooks/templates`.

## Template format

```
<id>/
  workbook.json   # name, description, Brief fields, first move, pages, sections
  AGENTS.md       # agent guide, copied to the workbook's "How to work here" page
  pages/*.md      # starter content for the Brief and each page
```

- **Sections and pages.** A section is either a page of its own (`file`) or the part of a shared page under a `## <section title>` heading (`in`: a page id from `pages`, or `brief` for the Brief), so related sections can share one page. The template is checked for each heading. The Coding template is the Brief (with Open questions) plus three pages: How to work here, Plan (Steps, then Follow-ups) and Decisions & findings. A plan step is the work for one chat, ending in one commit; its tasks are indented checkboxes under it (chores, review comments, and jobs only the user can do, marked `(you)`), and a step can only be marked done once they're ticked.
- **Copied once.** Creating a workbook copies the template into a Pages Project: `pages/brief.md` (with `{{field}}` placeholders filled from the Brief fields) becomes the Project document, and the guide and each page become Pages. After that the workbook owns its content; changing a template never changes existing workbooks.
- **All sections are created up front**, so people, agents and the app always find them.
- **Item types** are the shared vocabulary every template is built from: `plan-step`, `task`, `decision`, `finding`, `question`, `reference`, `artifact`, `note`. Each section declares the item type it holds; the app and the workbook tools address sections by id and item type, never by title.
- **Item formats** are defined once, in the guide; each page's starter content says only what belongs there. Workbook tools (agent tools contributed by `kilo.workbooks`, which find the calling session's active workbook) own the write path and guarantee them; until they exist, agents write the formats with the Pages MCP tools.
- **The app reaches Pages through Kilo's Pages MCP connection** (the user signs in to the `pages` MCP entry), and every chat in a session on a workbook is given its Brief and guide as instructions (`kilo.core/chat-config`, read from Pages on the chat's first send).

## In the app (prototype, behind the `workbooks` flag)

- **Working in a workbook:** the New Session page's location row ends with **Workbook** (a `kilo.work-sessions/new-work-session-setting`, after Workspace, Use and Branch): a searchable picker built to the dropdown standard (`packages/ui/src/lib/menu-styles.ts`, as the workspace picker: every workbook, those used in the page's workspace first, then the rest by last use; **No workbook** to clear it; **New workbook** pinned under the list). Choosing starts nothing: whatever the page then starts (a first message, a tool, an empty session) is put in the workbook before it opens, so its chats get the workbook's instructions. Choosing a workbook also suggests a short first message in the New Session draft (`kilo.chat/composer` `prefillNewSession`), never over text you typed: the template's first move for a workbook just made here, otherwise say where it was left and what's next. Send it, edit it, or write your own. With no say on what to work on, the agent says where it was left and what's next, then lets you decide; in a new workbook it makes the guide's first move. The choice stays for later sessions, as the workspace does. New workbook opens a two-step wizard (as Add AI Provider): choose a template from a compact grid, filterable once there are many (Coding, or Blank: just a Brief and a Notes page), then name it and fill in its Brief, optional fields folded into More details; it selects the workbook it makes.
- **Workbook tools** (`desktop_workbooks_*`): `read_workbook`, `add_plan_step` (with its tasks), `add_task`, `set_task_done`, `set_step_status`, `record_decision`, `file_item`, `set_where_i_left_off`. They find the chat's workbook from its work session and write the guide's formats.
- **In chats:** the open session's header shows its workbook; workbook tool calls render as one-line filing receipts.
- **Pages decides which workbooks exist.** A workbook is a Pages Project whose description starts with the marker `Workbook · <template name> (<template id>)` (older ones carry only the name). The picker refreshes the list from Pages when it shows and when it opens: it lists the marked Projects, shared ones included, and finds their guide and sections by page title (the template's, or every known template's when the template isn't on offer). A workbook's id is its Pages project id, so it's the same workbook on every machine; the app keeps the last list found, so it shows at once and offline.
- **Workbooks belong to the person, not a workspace.** Each reference records the workspaces it has been used in (starting a session on it records the session's workspace; creating it in one counts as the first use) and when it was last used. This only orders the picker, so work that spans workspaces, or happens outside any, keeps one workbook. This usage is kept on this machine only.
- **Pages** is reached through Kilo's own MCP connection to the user's `pages` server, on Kilo's global instance (not any one folder), so the `pages` entry must be in global Kilo config; kilo.workbooks is one of kilo.core's Kilo-server clients for this.
