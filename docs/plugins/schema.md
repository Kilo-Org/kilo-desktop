# Plugin schema

Every plugin, extension point, domain object, object type and context key in
the kernel and the bundled plugins. This is the app's public API: what a
feature can build on and what it would add to. Check it before designing a
feature (see [Designing a feature](../plugin-architecture.md#designing-a-feature)).

Everything below the line is generated from each plugin's `plugin.json` and
the definitions in its `./contracts` (and the kernel's built-ins). Run
`pnpm docs:schema` after changing a manifest or a definition; `pnpm lint`
fails while this page is out of date. Contributions and dependents come from
manifests only: runtime contributions (`sdk.extensions.add`) are not listed.
In the running app, Settings → Developer → Diagnostics (behind the `developer`
flag) shows the same model live, with each definition's types.

How to use each building block: [extension points](./extension-points.md),
[domain objects](./domain-objects.md), [commands and context
keys](./commands-and-keys.md).
