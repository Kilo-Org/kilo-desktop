# Boundary Register — Trust Boundaries → Files → Candidate Threats

Shared, agent-facing index of the app's trust boundaries. Both security skills
consume it: `security-architecture` uses it as the seed for the overview's
trust-boundary section; `threat-model` uses it to decide which files to read per
STRIDE+Privacy question (`.agents/skills/threat-model/references/template-questions.md`
says _what to answer_; this file says _where to look_). Threats in the Candidate
threats column are hypotheses to verify, not findings.

Kept in sync with the code by [`register-sync.md`](./register-sync.md), which
both skills run as their first step.

Three rules:

1. **Seed, not exhaustive** — also look for threats NOT listed here when reading
   code. The register accelerates; it must not blinker.
2. **Maintenance trigger** — a PR that adds a trust boundary (new plugin sidecar,
   network listener, credential store, file IPC) must add a row. This file absorbs
   architecture drift so the skills and `template-questions.md` stay stable.
3. **No line numbers** — the Files column names paths only, never `file:line`.
   Line references rot too fast for a committed file; the sync strips them on
   sight.

Note: features migrate `apps/ → plugins/ → external repo` (see `CONTEXT.md`), so
boundary files WILL move — the sync exists to catch that.
